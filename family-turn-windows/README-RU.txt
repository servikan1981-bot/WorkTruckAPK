TURN для видеозвонков «Наша семья» (Windows)

Сервер сообщений на HTTPS доставляет приглашения и команды, но не пересылает
сам видеопоток. Этот отдельный TURN-сервер помогает при звонке через разные
Wi-Fi/мобильные сети. Компьютер должен быть включён во время звонка.

1. Распакуйте архив в отдельную папку, например C:\OurFamily\turn.
   Не заменяйте файлы действующего сервера сообщений и не трогайте его data.
2. Запустите start-turn.cmd. Введите ПУБЛИЧНЫЙ IPv4 домашнего интернета.
   Программа создаст локальный turn-config.json с отдельным случайным паролем.
3. В Keenetic в разделе переадресации портов создайте ДВА правила на IP
   компьютера с сервером, например 192.168.1.139: UDP 3478 -> 3478 и
   UDP 49160-49259 -> 49160-49259. Это не правило KeenDNS для веб-сервера.
   В PowerShell администратора разрешите входящие UDP на частной сети:
   New-NetFirewallRule -DisplayName "OurFamily TURN" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 3478,49160-49259 -Profile Private
   Если локальный IP компьютера изменился, обновите правила на роутере.
4. На каждом телефоне в настройках профиля заполните ТРИ поля TURN URL,
   пользователь и пароль, которые показывает окно start-turn.cmd.
   В URL обязательно укажите ?transport=udp. На телефоне, который бывает
   дома на Wi-Fi, добавьте через запятую также локальный адрес компьютера:
   turn:5.227.60.178:3478?transport=udp,turn:192.168.1.139:3478?transport=udp
   Подставьте свои актуальные IP. Кнопка проверит TURN, затем сохранит данные.
5. Испытайте звонок: один телефон по Wi-Fi, второй с выключенным Wi-Fi по
   мобильным данным. На экране должен появиться живой кадр собеседника.

Не публикуйте turn-config.json и не присылайте пароль в чат. Если меняется
публичный IPv4, исправьте publicIp в turn-config.json и перезапустите сервер;
скорректируйте URL TURN на телефонах. Для проверки снаружи /health сервер
сообщений не подходит: это отдельный протокол UDP.
